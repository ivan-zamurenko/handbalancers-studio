# Навчаємося програмуванню на Handbalancer’s Studio

Домовленість власника 2026-11-24: продукт — петпроєкт для портфоліо й
підготовки до співбесід. Початковий рівень Python — з основ.

## Робочий цикл

1. Агент пояснює одну невелику задачу з поточного етапу продукту.
2. Показує потрібне поняття на іншому короткому прикладі.
3. Дає заготовку, очікувані результати й команду перевірки.
4. Власник пише свою ділянку; агент працює над незалежною задачею,
   не редагуючи навчальний файл без нового доручення.
5. Разом розбираємо результат: що правильно, причину помилки та спосіб перевірки.
6. Закріплюємо тему двома-трьома питаннями для співбесіди.

Одне завдання за раз, орієнтовно 15–30 хвилин без дедлайну.
Готове рішення не підставляється замість спроби власника. На прохання
можна дати підказку або пояснений розв’язок. Затримка вправи не блокує
незалежну роботу над продуктом; за user-owned файли відповідає власник.

Код з навчальної папки не імпортується застосунком і не отримує .env,
DB credentials, справжніх акаунтів або відео. Корисну реалізацію переносимо
в продукт тільки з review, тестами й потрібними правилами локалізації.
Авторизацію, платежі, RLS і міграції спочатку читаємо й обговорюємо на
перевірених прикладах; неперевірений навчальний код не захищає реальні дані.

## Послідовність

| Етап навчання | Невелика задача | Зв’язок із Studio |
|---|---|---|
| 1. Змінні, числа, функції, рядки | [Секунди → хвилини:секунди](01-duration.md) | Відображення тривалості |
| 2. Списки, словники, цикли | Підсумувати synthetic записи підходів | Звіти тренування |
| 3. Умови, помилки, тести | Відхилити неправильний результат | Валідація введення |
| 4. HTTP, JSON, типи | Розібрати навчальний API response | Frontend/backend зв’язок |
| 5. SQL і зв’язки | Прочитати власні synthetic записи з test DB | Історія й ownership |
| 6. Чисті функції та геометрія | Обчислити просту метрику на fixtures | Біомеханіка |

Наступну вправу деталізуємо після попередньої, не створюємо весь курс наперед.
За потреби додаємо HTML/CSS/JS на невеликих UI-задачах.

Для портфоліо після кожної задачі записуємо три речення: яку проблему
розв’язано, як перевірено, що власник написав самостійно. На співбесіді
пояснюємо справжній внесок і використання AI, не приписуємо весь продукт
власноручній роботі.
