# Перевірка сайту — 2026-09-13

Перевірено новий застосунок `server/` на macOS arm64, Python 3.13, PostgreSQL 14.19, Chrome через Playwright. Адреса: http://127.0.0.1:8000/.

## Сервер і дані

- `python3 scripts/local.py test`: **83 passed**, 4 deprecation warnings у залежностях. Тести використовували лише окрему `studio_test` і випадкові схеми.
- Міграція `0001_initial` застосована до локальної `studio`; `alembic check`: No new upgrade operations detected.
- Перевірено валідацію, збереження та ізоляцію анкет, ротацію сесії, CSRF, заборону сторонніх Host і завеликих запитів, production-заборону demo, expiry підписки та очищення прострочених сесій.
- OAuth/JWT і Stripe перевірені fixtures: nonce/state, повторне використання callback, власник і ціна платежу, підпис webhook, повторні й неупорядковані події. Це не тест із живими обліковими записами провайдерів.
- Ruff успішний; `pip check`: No broken requirements found.
- `python -m unittest discover -s deploy/tests -q`: 14 перевірок пройшли, 1 пропущена через відсутність Docker. YAML і shell-синтаксис перевірено; це не підтверджує контейнерний запуск. Метадані трьох Docker tags підтверджено через Docker Hub, без завантаження образів (`deploy/image-tags.checked.json`).

## Браузер

`scripts/check-site.mjs` успішно пройшов локальний шлях із реальною PostgreSQL: дві цілі → досвід → 60+ хв → три дні → demo-реєстрація → Plus → demo-оплата → кабінет → reload → English → logout.

Перевірено українську за замовчуванням, збереження чернетки після reload, клавіатурний вибір, порожню анкету й захист переходу до кабінету. Не виявлено необроблених JavaScript-помилок. На 320, 390, 768 і 1440 px немає горизонтального переповнення для головної, тарифів, анкети, privacy та terms.

Дванадцять axe-перевірок WCAG 2 A/AA та 2.1 AA — без виявлених порушень. Це автоматизований контроль, а не сертифікація повної доступності. Переглянуто скриншоти desktop і mobile.

Результати й скриншоти: `.local-tools/verification/site/`. Скриншоти перед збереженням завантажують також відкладені зображення; сам сайт зберігає lazy loading для зображень нижче першого екрана.

## Що ще не перевірено

Живі Google/Apple OAuth і Stripe, Linux Docker build, запуск Compose, HTTPS/Certbot, production backup/restore, навантажувальні випробування та ручне тестування в Safari/Firefox. Інструкції й конкретні межі контейнерного розгортання — у `deployment.md`. AI, відеоаналіз і тренувальний журнал не входять до реалізованого етапу сайту.

## Правки за відгуком користувача

Перевірено 17 груп браузерних сценаріїв: спільну центральну вісь заголовка й опису напрямів, прокручування верхнього посилання тарифів, однаковий початковий стиль карток, збільшення лише вибраної картки та окреме продовження. Новий онбординг не містить головної цілі й питання спорядження; API окремо зберігає 60+. Четвертий день не можна обрати, зняти вибір і замінити день можна.

Переходи каруселі перевірено зі звичайною анімацією та reduced motion. Виправлено можливість втрати швидкого натискання під час переходу: контролі блокуються до завершення анімації. На телефоні нове питання повертається у видиму область. Серверні перевірки підтверджують читання старих анкет без мутації та відхилення несумісних нових відповідей.

Скриншоти `directions-desktop.png`, `onboarding-time.png`, `onboarding-days.png` та мобільні варіанти збережено разом із загальним звітом. Системна типографіка використовує San Francisco на macOS; файли Apple-шрифтів не копіювалися у вебзастосунок.

Остання правка: Plus вибрано за замовчуванням, рекомендаційний бейдж приглушено-зелений; явний вибір іншого пакета зберігається. Довгі тире в текстах активного сайту замінено на звичайний дефіс. Браузерний сценарій доповнено відповідними перевірками.

Шапка та скорочення текстів: перевірено назву «Логін», центральну вісь анімованого підкреслення та його hover-стан, відсутність блоку порівняння й примітки під тарифами. 17 груп браузерних сценаріїв пройшли; 12 axe-станів без виявлених порушень. Повторна серверна перевірка для цих суто frontend-змін не потрібна.

Блок трансформації: 18 груп браузерних сценаріїв пройшли. Перевірено однакові font family/size/weight рядків hero, два графіки й пояснення ілюстративності, три кроки таймлайну, hover-зум напрямів і відсутність повторюваних блоків. 12 axe-станів без порушень. Переглянуто desktop/mobile скриншоти трансформації. Це презентаційна схема, а не результат аналізу клієнтських даних.

Перевірено 4 перемикачі потреб, єдиний активний стан, відповідні кроки й data-direction CTA, 2 графіки для кожної ситуації та відсутність переповнення для різних потреб на мобільному. ## Безперервна інтеграція, 2026-09-14

Додано `.github/workflows/ci.yml`. Перевірки більше не залежать від однієї машини: вони запускаються на кожен push у `main`, на кожен pull request і вручну.

Завдання `quality`: `ruff check`, `ruff format --check`, `prettier --check .`, серверні тести проти сервісного PostgreSQL 14, deployment unittest, `alembic upgrade head` та `alembic check`. Завдання `browser`: піднімає застосунок, чекає на `/health/ready`, потім запускає `check-site.mjs` і `check-account-flow.mjs` у Chrome; лог застосунку зберігається артефактом лише при збої.

CI не використовує `scripts/local.py test`, бо той скрипт вимагає приватний `server/.env` і локальний порт 55432. Замість цього pytest отримує лише `TEST_DATABASE_URL`; fixture і далі відмовляється працювати з будь-якою БД, чия назва не закінчується на `_test`. Цей виклик відтворено локально перед комітом: 136 passed. `SESSION_SECRET` для CI генерується на кожен запуск через `openssl rand`, тому жодного схожого на секрет літерала у Git немає. Жодних реальних облікових даних провайдерів у CI немає, тому живі Google/Apple, Stripe і SMTP залишаються неперевіреними.
