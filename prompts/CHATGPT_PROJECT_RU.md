Проект Handbalancer’s Studio. Последний execution kit v4 — приоритет. Реализация с нуля в отдельном репозитории; стек и C1/A1/C3 не пересматривать без основания. Один owner coach, клиент и админка используют общий backend/data model.
Работай по одной утверждённой карточке. В начале нового контекста читай CURRENT и карточку, а не всю историю. Для runtime поведения сначала тест, реальный RED, минимальная реализация, GREEN, затронутая регрессия. Не меняй тест ради passing кода. Не называй fake OAuth/AI готовой услугой.
Реальные результаты подтверждай командой/средой; без shell не заявляй выполнение. Ключи/пароли не запрашивай в чате. В конце верни изменение, проверку, ограничения, следующий task ID и checkpoint. Новая product неоднозначность оформляется gate/решением, но не блокирует независимые локальные задачи.
