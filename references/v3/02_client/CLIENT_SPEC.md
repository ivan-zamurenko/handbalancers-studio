# Клиентская часть — C1 и C3

## Цель
Клиент видит один личный план, следующее реальное занятие, историю и понятный статус сопровождения.
Изменение календаря не создаёт скрытые параллельные программы. Доступ определяется сервером.

Мобильная навигация: Сегодня / Программа / История / Профиль. Календарь и библиотека доступны из программы и карточки «Сегодня». C3 — focus-layout без отвлекающей общей навигации.

## Сценарий «Хочу это занятие сегодня» на Essential
1. Выбрать тренировку, а не запускать всю вторую программу.
2. Выбрать день. Если день занят, явно предложить замену по умолчанию.
3. Дополнительное занятие добавлять только отдельной командой.
4. Проверить время, утверждённую совместимость, соседние занятия, фактически выполненное.
5. Показать список изменений: что заменится, что переместится, что останется.
6. Подтвердить; сервер повторно проверяет актуальность плана и сохраняет одним commit.
7. При устаревшем preview построить новый. При невозможности согласования предложить другую дату/занятие, не ставить сверху молча.

Дополнительное занятие из другого источника не закрывает этап основной программы, если не существует разрешённой эквивалентной замены.
Незаписанная внешняя нагрузка неизвестна системе. В интерфейсе не обещать абсолютное отсутствие перегрузки.

## Сценарий основной программы
Выбор опубликованного шаблона → предварительное будущее расписание → подтверждение → назначение.
Замена закрывает старое текущее назначение и создаёт новое. Прошлые назначения/результаты сохраняются.
В Pro/Pro+ выбор желаемой программы может стать запросом владельцу; не разрушать действующее персональное назначение из каталога.
В Plus изменения согласуются с активной AI-адаптацией и ожидаемой ревизией плана.

## Тренировка C3
Start → восстановление существующей или одна новая session → запись подходов → отдых/пауза → явные пропуски → Complete.
Любой лог принадлежит человеку, сессии и слоту подхода. Повтор после таймаута не создаёт второй результат.
Незавершённый ввод сохраняется локально с разделением пользователей; «Сохранено» — после подтверждения сервера.
Отсутствующее значение, нулевой факт и пропуск — разные состояния.
Видеоссылка необязательна для Complete, но отсутствие видео видно в статусе проверки.
Тема меняется без перерисовки формы и потери ввода.
Если доступ/сессия потеряны, сохранить локальный черновик и объяснить, почему сервер пока не принял запись.

## Прогресс
Считать завершённые факты, не количество открытых экранов.
Неделя начинается в воскресенье 00:00 по timezone профиля. Новая неделя — новый интервал, не удаление истории.
Тема использует местное время устройства; timezone тренировочной недели — отдельная настройка.
Плановый бюджет недели хранить отдельно от прогресса основной программы. Дополнительное занятие учитывается в факте, но не изменяет автоматически знаменатель недельной цели. Явные изменения цели версионируются.
Не суммировать одну и ту же тренировку как запланированную и выполненную дважды.

## Обязательные состояния
Страница: loading / empty / ready / error / forbidden.
Форма: dirty / validating / saving / saved / failed / conflict.
Доставка факта: local_draft / pending_sync / saved / rejected.
Отчёт: создан по фактам / ожидает техники / проверен / обновление после нового evidence.
Не изображать неподключённый анализ как работающий.
