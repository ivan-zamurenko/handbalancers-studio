# Админка владельца-тренера — A1

## Область
Этот план относится к админке в той же мере, что к клиентскому кабинету.
Владелец создаёт каталог и методику, назначает программы, управляет разрешёнными действиями, видит факты, проверяет выполнение и меняет будущее.
Это не только панель «просмотра клиентов» и не отдельный backend.

## A1 и адаптивность
Desktop: три связанные области — список клиентов/задач, данные выбранного клиента, текущая проверка.
Mobile: переключение «Клиенты / Данные / Проверка», сохранение выбранного клиента и черновика, а не три колонки одна под другой.
Редактор программы, правила и календарь открываются как отдельные рабочие представления этой дизайн-системы. Не помещать весь функционал в один экран A1.
Светлая/тёмная тема и ручной выбор работают и у тренера по его собственному времени, независимо от клиента.

## Создание программы
Создать упражнение → опубликовать его ревизию → собрать программу → проверить → опубликовать дерево программы.
Общая программа и персональное изменение различаются. Изменение для одного человека создаёт его приватную производную, не меняет каталог и остальных клиентов.
«Сохранить черновик» не равно «Опубликовать». Опубликованное дерево неизменяемо, включая цели подходов.

## Контроль нагрузки
Для конкретного плана владелец задаёт разрешённые переносы, списки эквивалентных замен и доступные дополнительные занятия.
Essential использует общие опубликованные правила, а не индивидуальный человеческий review.
Pro/Pro+ используют общие правила плюс правила назначенного владельцем плана. Сохраняется решение владельца о нагрузке.
Результат проверки правил: разрешено / конфликт / недостаточно данных / нужно решение тренера. Эти состояния не являются медицинским заключением.
Численные интервалы и границы нагрузки отсутствуют до ввода методики владельцем.

## Запрос клиента на изменение
Клиент выбирает вариант вне разрешённых → создаётся запрос без изменения календаря.
Владелец открывает актуальный план и фактические результаты → получает новый preview → одобряет/отклоняет с объяснением.
При подтверждении проверить revision заново. Принятый запрос помечается applied только после успешного commit.
Не создавать две системы утверждения: запрос и preview являются шагами одного сценария.

## Проверка
Задача для Pro/Pro+ собирает недельный контекст по контракту. Не обещать обязательный ручной review каждого занятия/всех Plus.
Владелец видит план и факт, просмотренный вариант видео и предыдущие опубликованные выводы.
Приватная заметка хранится отдельно; она не попадает в API клиента, письмо или экспорт по случайному сериализатору.
Публикация feedback не меняет программу автоматически. Изменение будущего — отдельная команда.
Позднее видео помечает проверку нуждающейся в обновлении; старый опубликованный вывод остаётся в истории.

## AI и рабочие заметки
Владелец может использовать свои замечания для контекста конкретного клиента в согласованном анализе.
Чтение заметок внешним AI и использование для обучения общей модели — разные цели обработки; настройки доступа/разрешения обязательны.
Не отправлять все private notes провайдеру по умолчанию и не обещать автоматическое обучение весов.

## Права и аудит
Единственный владелец не означает отсутствие контроля доступа. Рабочая роль coach и связь с клиентом проверяются сервером.
Глобальная диагностика подписок не даёт автоматического доступа к любому приватному видео.
Сохраняются автор, причина и время изменения программы/расписания/оценки.
Тема тренера и тема клиента независимы. Данные же о плане, факте и опубликованной проверке общие.
