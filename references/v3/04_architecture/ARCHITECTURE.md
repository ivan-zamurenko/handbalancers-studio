# Архитектура общей системы

## Решение
Модульный монолит. Один FastAPI backend обслуживает клиентский кабинет и админку, общую PostgreSQL и проверенные внешние интеграции.
Не создавать два независимых сервиса планирования, два конструктора предметных правил или две таблицы фактов «для клиента» и «для тренера».

Браузер (Jinja/HTML/CSS/vanilla JS) → HTTPS/REST → FastAPI: проверка сессии/прав → доменная команда → транзакция SQLAlchemy → PostgreSQL.
Supabase Auth управляет идентичностью; Stripe — внешние события оплаты; источник видео/AI подключаются через адаптеры после выбора.

## Модули
| Модуль | Ответственность |
|---|---|
| auth / accounts | Сессия, доверенный профиль, роль, предпочтения |
| catalog | Упражнения, переводы, immutable ревизии |
| programs | Общие/приватные программы, конструктор, публикация |
| planning | Один личный план, назначение, совместимость, preview/commit, разрешения и запросы |
| training | Start/log/pause/resume/complete, snapshots, факты |
| reviews | Задачи и публикации тренера, отдельные private notes |
| assessments | Тестовая программа, протокол, критерии, вывод по фактам |
| media | Идентификаторы провайдеров, доступ, версии evidence; не произвольный downloader |
| analysis | Целевые задания AI, наблюдения и предложения; не произвольные права на данные |
| billing | Проверенная подписка и entitlements |
| progress | Недели, фактическое время и сопоставимые результаты |
| shared | Общие ошибки, аудит, идемпотентность, проверка ревизий |

## Планировщик
Вход: snapshot текущего личного плана, факты выполнения, выбранное действие, доступные дни/время, published правила и разрешения владельца.
Порядок: авторизация → целостность входов → время → совместимость → соседний контекст → выбор кандидата с минимальным изменением → diff.
Нет числовых нормативов «из головы», медицинских гарантий или использования AI для обычного календаря Essential.
Выход: allowed/conflict/insufficient_data/requires_approval и объяснения/список изменений.

Планировщик сам не записывает в БД при просмотре. Apply повторяет значимые проверки в транзакции.
После start/completion/correction меняется контекст нагрузки; такой факт должен инвалидировать несовместимый старый preview. Один row_version плана или контекстный fingerprint должен учитывать эти изменения, не только переносы календаря.

## Авторизация и владение
Supabase JWT/сессия проверяются сервером; роль не читается из редактируемых пользователем metadata.
BFF с защищённой cookie — проектная отправная точка; lifecycle refresh/logout/revocation реализовать и проверить, а не считать готовым.
CSRF для cookie-команд; server-side entitlement; строгая проверка owner/coach access.
DB runtime не должен обходить RLS. Пул соединений не переносит контекст одного пользователя в другую транзакцию.
Составные связи доказывают принадлежность сессии, упражнения, видео и анализа одному человеку.
Публичные отзывы и приватные заметки — отдельные запросы и модели ответа.

## Надёжность
Idempotency key + request hash для эффектных команд. Повтор с тем же ключом и другим телом — конфликт.
CAS/row_version для редактирования и preview; короткие root-lock транзакции при публикации дерева.
Complete атомарно сохраняет результат, occurrence и версию отчёта. Асинхронный внешний анализ не удерживает DB-транзакцию.
Durable job/inbox можно хранить в PostgreSQL; отдельный worker того же кода допускается при необходимости внешнего AI. Это не переход на микросервисы.
Timeout/ошибка внешнего сервиса не создаёт вымышленное «успешно». Повтор не удваивает адаптацию.

## Видео и AI
Модуль media разделяет ссылку для человека, пригодность evidence и возможность получения материала адаптером.
YouTube приоритетен. Vimeo/Drive кандидатны, не активны автоматически.
URL с разрешённым доменом сам по себе не разрешает произвольный сетевой fetch; реализовать строгий адаптер и ограничения доступа.
Никакого публичного режима по умолчанию, передачи без разрешения или скрытого копирования видео.
AI получает минимальный допустимый контекст, выдаёт структурированное предложение. Apply принадлежит доменному сервису.
Частные заметки как контекст клиента и обучение общей модели — независимые цели.

## Коммерческий путь и релиз
Цели/уровень/время/дни → тариф → регистрация/вход → Checkout → кабинет.
Подтверждённый webhook, а не success URL, определяет платный доступ.
OAuth/SMTP/Stripe/AI, backup/restore и production не проверялись при упаковке. Не объявлять их готовыми.
Решение о новом schema baseline не отменяет сохранение текущего пользовательского кода и отдельное подтверждение удалённых destructive действий.
