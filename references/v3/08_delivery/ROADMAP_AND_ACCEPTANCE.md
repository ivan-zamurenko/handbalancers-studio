# Последовательность разработки и приёмка

## Порядок
| Этап | Законченный результат |
|---|---|
| 0. Вход в проект | Прочитан v3, определён фактический репозиторий, просмотрен git status, сохранена пользовательская работа |
| 1. Основа | Новая локальная baseline, доверенный профиль и Auth adapter; тесты owner/role/refresh/logout |
| 2. Каталог | Упражнение, перевод, неизменяемая ревизия; тренерский ввод |
| 3. Программа | Общий конструктор member/coach, private/catalog, validation/publish/version |
| 4. План | Один план, текущая основная программа, единый календарь и дополнительные occurrence |
| 5. Первый сквозной срез | Тренер создаёт/назначает → клиент выполняет → тренер публикует feedback |
| 6. Планирование | Essential replace/add/move + rules + preview/commit; ограничения и запросы Pro |
| 7. Оценка | Протокол владельца и тестовая программа через тот же движок |
| 8. Интеграции | Настоящие billing/Auth/SMTP проверки; выбранный способ видео |
| 9. AI | Закрытая проверка по методике, shadow-mode, затем ограниченная автоадаптация Plus |
| 10. Релиз | Проверены обещания продаваемых тарифов, backup/restore, безопасность, реальные внешние пути |

Billing-права и безопасность проектируются с первого этапа, даже если live интеграции подключаются позже.
Не блокировать ручной сквозной срез до выбора AI-провайдера. Не запускать в продажу тариф с отсутствующей обещанной функцией.

## TDD
Зафиксировать сценарий → тест → наблюдаемый red по отсутствующему поведению/дефекту → реализация → green → рефакторинг.
Имеющиеся исторические логи tests не доказывают работу новой системы.
Проверки текущей упаковки находятся в `09_checks/`. Они не заменяют тесты приложения ниже.

## Ключевые приёмочные сценарии
| ID | Ожидаемый результат |
|---|---|
| CAT-01 | Каждый действующий тариф видит опубликованный общий каталог; чужой private недоступен |
| PLAN-01 | Два параллельных выбора основной не создают две текущие основные программы |
| PLAN-02 | Дополнительное занятие другого источника создаёт occurrence в том же плане, без второго назначения main |
| PLAN-03 | По умолчанию занятой день предлагает замену, не удваивает нагрузку |
| PLAN-04 | Нет допустимого сочетания — объяснение и альтернативы; нет скрытого apply |
| PLAN-05 | Недостаток метаданных — insufficient_data, не гарантия совместимости |
| PLAN-06 | Одно выполнение учтено один раз; нерелевантный источник не закрывает этап основной |
| PLAN-07 | После preview пришёл новый факт или правка — старый apply отвергнут |
| PLAN-08 | Существующая active/paused session не меняется перепланированием |
| COACH-01 | Неразрешённое клиентское изменение становится запросом без изменения расписания |
| COACH-02 | Одобрение проверяет актуальную ревизию; разрешённые переносы не требуют ручного approval |
| COACH-03 | Private notes отсутствуют в клиентском ответе/экспорте/уведомлении |
| COACH-04 | Publish feedback не меняет будущую программу автоматически |
| VER-01 | Ни один child published программы не меняется обычным UPDATE |
| VER-02 | Персональное изменение не затрагивает каталог/чужие назначения |
| TRAIN-01 | Повтор Start/Complete после таймаута не удваивает факт |
| TRAIN-02 | Offline/reload сохраняет собственный draft, другой аккаунт его не видит |
| TRAIN-03 | Два устройства не молча перезаписывают один подход |
| TRAIN-04 | Missing/0/skipped различаются; partial не становится full |
| TRAIN-05 | Вручную записанное занятие не выдумывает упражнений/целей |
| VIDEO-01 | Новая ссылка создаёт новую evidence-version, старый review сохраняет исходную |
| VIDEO-02 | Недоступное/непригодное видео не даёт уверенную оценку техники |
| AI-01 | AI не может менять факты, роли, цену или общий каталог |
| AI-02 | Proposal stale после изменения тренером не применяется |
| AI-03 | Repeat apply создаёт одну будущую версию и один diff |
| ASSESS-01 | Тест использует обычные set_logs, без второго журнала фактов |
| ASSESS-02 | Критерии и версия методики сохраняются; missing evidence не not_ready |
| THEME-01 | auto/light/dark, границы времени и ручной приоритет |
| THEME-02 | Смена темы не теряет ввод, draft feedback и выбранного клиента |
| TIME-01 | Воскресная граница, DST/поездки и корректная история без удаления |
| BILL-01 | Redirect без webhook не активирует доступ; repeat event не удваивает эффект |
| SEC-01 | Подмена IDs проверяется на всей цепочке plan/session/exercise/video/review |
| SEC-02 | RLS работает под реальной ограниченной runtime-ролью; pool не течёт контекстом |

Нормативы нагрузки в автоматических тестах — синтетические fixtures, не методика production.
Тесты запускать только на изолированной базе, не на remote/production.
