## Сначала тесты
| Тест | Что обязан доказать |
|---|---|
| `invalid_signature_rejected` | Неверная/старая подпись не меняет БД. |
| `raw_body_verified` | Пересериализованный JSON не используется вместо raw payload. |
| `duplicate_event_once` | Повтор event.id подтверждается без нового эффекта. |
| `database_failure_retries` | Ошибка durable insert возвращает retryable non-2xx, не теряет event. |
| `no_payload_logs` | PII/секреты webhook не печатаются. |

Команда проверки (создать test-файл до реализации):
```sh
uv run pytest server/tests/integration/billing/test_webhook_inbox.py -q
```

Ожидаемый RED: как минимум один из новых тестов выявляет именно отсутствующее поведение текущей карточки. Ошибки настройки исправляются отдельно и не выдаются за TDD-доказательство. Для чисто инфраструктурной задачи проверяется её реальная гарантия, а не assert(true).
