## Сначала тесты
| Тест | Что обязан доказать |
|---|---|
| `one_account_trial` | Одновременные Essential/Plus Checkout не получают два trial. |
| `pro_no_trial` | Pro/Pro+ не получают trial через body hack. |
| `card_required` | Checkout подтверждает сбор карты по согласованному flow. |
| `failed_attempt_recovery` | Reservation снимается/подтверждается только после проверки реального исхода Stripe. |
| `no_trial_from_redirect` | Клиентский redirect не потребляет/не выдаёт trial сам. |

Команда проверки (создать test-файл до реализации):
```sh
uv run pytest server/tests/integration/billing/test_trial_claims.py -q
```

Ожидаемый RED: как минимум один из новых тестов выявляет именно отсутствующее поведение текущей карточки. Ошибки настройки исправляются отдельно и не выдаются за TDD-доказательство. Для чисто инфраструктурной задачи проверяется её реальная гарантия, а не assert(true).
